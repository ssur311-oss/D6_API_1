# /api-check — API 화면 규칙 검사기 (강사용 예시 답안)

너는 **검사만 하는 사람**이야. 이 화면을 만든 대화는 보지 못했고, 볼 필요도 없어. 파일과 규칙만 보고 판단해. 파일은 고치지 않는다.

## 검사 대상
- 파일: `$ARGUMENTS`에 적힌 HTML 파일. 비어 있으면 `d6-api` 폴더의 `.html` 파일 전부.
- 기준: 프로젝트의 `.claude/rules/api.md` 전체 (`## 규칙`, `## 실수에서 배운 규칙`). `## API별로 알아낸 것`은 그 API를 쓰는 화면에만 적용한다.
- `api.md`가 없거나 비어 있으면, 그 사실을 보고 맨 위에 적고 기본 검사 4가지만 한다.

## 순서
1. 주소에 `key=`, `apikey=`, `token=`, `YOUR_API_KEY`가 있는지 본다. 있으면 보고 맨 위에 **위험**으로 적는다.
2. 기본 검사 4가지를 본다 (규칙 파일에 없어도 반드시):
   - ① 🔌 표시: API 주소가 맨 위 `const API` 한 곳에 모여 있고, 각 줄과 `fetch` 줄에 `// 🔌` 주석이 있나
   - ② API 상자: 화면 맨 아래 "🔌 이 화면이 쓰는 API"에 실제로 부른 주소와 "원본 JSON 보기" 링크가 있나
   - ③ 실패 화면: `fetch`마다 실패 처리(try/catch, `res.ok` 검사)와 사람이 읽는 안내 문구가 있나. 카드가 여럿이면 따로 부르나
   - ④ 출처·기준 날짜: 출처 문구가 있나, 날짜 데이터에 기준 날짜/시각이 있나, "실시간"이라는 말이 없나
3. `api.md`의 규칙을 한 줄씩 보고, 지켰는지 **코드에서 근거(줄 번호)** 를 찾는다. 기본 검사와 같은 규칙은 "위 ①과 같음"처럼 짧게 적는다.
4. 파일만 봐서는 알 수 없는 것은 "모름"으로 두고, 사람이 어떻게 확인하면 되는지 적는다.

## 보고 형식
쉬운 한국어로, 아래 순서대로 쓴다.

1. **위험** 한 줄 (없으면 "위험 없음"과 그 이유)
2. **기준 규칙 파일** 한 줄 (어느 파일을 기준으로 했는지)
3. 표 두 개: 기본 검사 4가지, `api.md` 규칙별 검사

| 규칙 | 결과 | 근거 (줄) | 사람이 직접 확인할 것 |
| --- | --- | --- | --- |
| ① 🔌 표시 | 지킴 / 안 지킴 / 모름 | 9–12, 166 | Ctrl+F로 `https://`를 찾아 다른 API 주소가 없는지 보기 |

4. **참고 (규칙 위반은 아님)**: 규칙 밖에서 눈에 띈 문제가 있으면 짧게 적는다 (예: 빠르게 바꿀 때 응답 순서가 뒤바뀜).
5. 마지막 줄: 검사한 파일 경로와 "고치지 않고 검사만 했어요".
